# Recording opening tier (ask 288)

With HLS enabled, `MEDIA_HLS_STARTUP_SECONDS` chooses how many opening seconds use R2 (180 by default, 0 disables, maximum 300). Ask 288 explicitly requests this placement enabled. Later segments use B2. Small initialization segments remain on R2; a packed chunk crossing the boundary stays on R2 as a whole. R2 answers without an `Access-Control-Allow-Origin` header, so a browser in CORS mode (native HLS and hls.js both) cannot read a cross-origin redirect to it; an unpacked R2 row is therefore streamed through Media like a packed slice, which carries Media's CORS headers. Without that, the init segment fails and the page falls back to the complete file (or stops playing). The original complete file is untouched.

The existing heavy worker runs `object.startup-tier` after cuts and lazily when a master playlist is read. A public read does not wait for a copy. Lazy requests are capped by `MEDIA_HLS_BACKFILL_PER_HOUR` (20 by default), the queue's tenant limit, a ten-minute in-process throttle and a source/policy idempotency key. First-time access to an old recording can therefore still use B2 until the job completes. Each job copies at most 512 MiB and takes at most 30 minutes; unavailable providers, holds and verification failures retain the current routing.

A joined recording uses its complete timeline: a later part does not get another three hot minutes. Clips do not retier their sources. Every move reads back the target's size and SHA-256, then commits under the same advisory locks as recuts/packs with a source snapshot check. Cancelled, changed or unverified copies are never published. Both R2 and B2 must be healthy. The read router still filters unhealthy providers; the segment route then uses the selected durable tier ahead of a retained local cache. `X-OV-Media-Provider` reports the actual provider on the Media response (including redirects and packed slices).

A durable, internal-only `storage.startup.cleanup` job keeps old copies for 360 seconds: the presigned URL lifetime is 300 seconds and the joined timeline cache is 20 seconds. It refuses held objects and removes a copy only if no timeline row still names it. Failed deletes retry in the light worker. Packing keeps provider boundaries and preserves the current provider for each chunk.

Validation: `ov test test/startup-tier.test.js`, `ov test test/timeline-cache.test.js` and `ov test test/media-timeline.test.js`, then the full suite. Production baseline and after-deploy measurements are in the PR and `~/openvibe/research-2026-11-10/player-starts.md`. The baseline recording (`/o/med_01M729VRTW6E3NPTTM008H0GAA`) used B2 at both `source/p1-000001.m4s` (0 s) and `source/p2-000019.m4s` (217.297 s). Once tiered, the first should report `X-OV-Media-Provider: r2` and the latter `b2`.
