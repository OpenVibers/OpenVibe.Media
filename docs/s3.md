# The S3 surface and zones

OpenVibe.Media answers a subset of the Amazon S3 API at `https://s3.openvibe.media`, path style
(`/<bucket>/<key>`). The design is ADR-031 in OpenVibe.Contracts, with its two amendments. A **bucket is a zone**:
a named object zone of one project environment. Zones are made and deleted only through OpenVibe.Zone
(https://openvibe.zone).

## Pieces

| Piece | File | What it does |
|---|---|---|
| Signatures | `server/s3/sigv4.js` | Verifies SigV4 (Authorization header and presigned query) and decodes aws-chunked bodies, checking each chunk's signature and the trailers. |
| Access keys | `server/s3/keys.js` | `ovk_` keys for one project environment: read, write or both, and optionally limited to some zones. Secrets are encrypted with `MEDIA_S3_KEY_SECRET` and shown once. |
| Zones | `server/s3/zones.js` | Media's copy of Zone's records. It resolves bucket names, gives each zone's namespace its quota, and runs zone deletion. |
| S3 routes | `server/s3/routes.js` | The operations below, dispatched by `Host` (`MEDIA_S3_HOSTS`). |
| Control doors | `server/s3/admin-routes.js` | `PUT/GET /internal/zones/:id` (Zone only, `media.zone.provision`) and `/api/v1/projects/:project/access-keys` (`media.access_key.manage`, on behalf of a project admin). |

## Operations

**Supported:**
- `PutObject`, in one request, including aws-chunked bodies. `Content-MD5`, `x-amz-content-sha256` and the `x-amz-checksum-*` headers and trailers are checked.
- `GetObject` (with ranges, conditional headers and presigned response overrides) and `HeadObject`.
- `DeleteObject` and `DeleteObjects`.
- `ListObjectsV2` and `ListObjects` (prefix, delimiter and pages).
- `ListBuckets`, `HeadBucket` and `GetBucketLocation`.
- Presigned GET and PUT, valid for 7 days at most.

**Not implemented:** multipart uploads, `CopyObject`, ACLs, policies, versioning, tagging and bucket deletion.
`CreateBucket` answers 200 for a zone that already exists, so tools that probe this way keep working.

## Rules

- **Two doors, one object.** An object written over S3 is an ordinary Media object: a `med_` id in the zone's namespace (`app.<project>[.sandbox].<zone id>`) with `zone_id` and `object_key` set. The native API reads, lists and deletes it, and the reverse works too.
- **The default zone.** It is the environment root. Over S3 it lists the environment's native objects under a derived key: the child namespace path, then the `med_` id. A key of that form cannot be written over S3.
- **Overwrite.** The new bytes are stored first. Then, in one transaction under the tenant's quota lock, the previous object goes through Media's deletion path and the new one becomes ready. A held object is neither overwritten nor deleted (`AccessDenied`).
- **Quotas.** A write is checked against the zone's `quota_bytes` and the environment's quota, before the bytes arrive and again after.
- **Zone deletion.** When Zone pushes state `deleting`, the zone answers `NoSuchBucket` at once. The minute sweep (`zones.sweepDeleting`) tombstones every object with no restore window and purges every copy. The status reports `objects_remaining` and `held_objects` until nothing is left. Then Zone marks the zone `deleted`: its name is retired, and keys scoped only to it are revoked.
- **HEAD through a proxy.** Cloudflare forwards a HEAD as a GET for paths it may cache (by extension: `.jpg`, `.bin`, `.zip` …), but SigV4 signs the method. A header-signed request with no body that arrives as GET and verifies only as HEAD is served as the GET, and the proxy returns just the headers. A presigned URL never gets this, because one may be shared for a HEAD alone; nor does any other method. Every S3 response is `Cache-Control: private, no-store`, so the edge never caches one (`cf-cache-status: BYPASS`). The fix at the edge itself is a DNS-only `s3.openvibe.media`.
- **No browser execution.** Every response carries `Content-Security-Policy: sandbox; default-src 'none'` and `nosniff`, whatever type the object declares.

## Tests

- `test/s3-zones.test.js` runs end to end with the AWS SDK for JavaScript v3: every operation, presigned URLs, isolation, quotas, holds, two doors and zone deletion.
- `test/s3-sigv4.test.js` checks the worked examples of the S3 API reference, including the chunk signature chain.

## Using it

```sh
aws configure set aws_access_key_id ovk_…        # issued on openvibe.zone
aws configure set aws_secret_access_key …        # shown once
aws configure set default.s3.multipart_threshold 256MB   # no multipart yet: one request per object
aws --endpoint-url https://s3.openvibe.media s3 ls s3://assets/
rclone config create oz s3 provider Other endpoint https://s3.openvibe.media access_key_id ovk_… secret_access_key … \
  upload_cutoff 256M no_check_bucket true
```
